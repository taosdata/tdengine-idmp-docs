# 8.6 AI 问答

**AI 问答**功能让您可以使用自然语言查询您的运营数据。无需编写 TDengine SQL 或在资产层次结构中逐层查找，您可以直接提问，例如"em-1 昨天的峰值电压是多少？"，并获得基于您实际数据的答案。

## 8.6.1 打开 AI 问答

点击顶部导航栏中的 **AI 问答**。这将打开路径为 `/ai` 的 AI 问答页面。

AI 助手名叫**小T**。

## 8.6.2 界面布局

AI 问答页面包含两个区域：

**对话历史（左侧面板）。** 之前对话会话的列表。点击任意会话可重新查看其对话内容。新会话以**没有历史问题**的空白状态开始。

**对话区域（中/右侧）。** 主交互区域，包含：

- 问候语：*"嗯，我是小T，有什么可以帮到您？"*
- 输入框上方的**专家标签行**，点击标签即可为该会话选择领域专家（见 [8.13 专家模式](./13-expert-mode.md)）
- 文本输入框
- 输入框左下方的**专家**按钮与**深度思考**切换按钮
- 输入框右侧的**麦克风按钮**，支持语音输入
- 输入框下方带刷新图标的**推荐问题**区域

## 8.6.3 提问

需要在未来时间或按日、按周重复执行只读分析时，可在会话中创建 [AI 定时任务](./13-scheduled-tasks.md)。定时任务需要单独配置后台授权，并在创建或修改时确认计划与时区。

在输入框中输入您的问题。按 **Enter** 发送，或按 **Shift+Enter** 换行而不发送。

您也可以按**麦克风按钮**使用语音输入。说出您的问题，系统将其转录到输入框中。

## 8.6.4 深度思考模式

**深度思考**切换开关将查询路由到深度思考模型（在连接管理中配置）。对于需要扩展推理的复杂多步问题，请使用此模式——例如，跨时间窗口关联多个属性，或请求根因假设。关于数据值的标准问题无需深度思考模式。

## 8.6.5 推荐问题

在输入框下方，**推荐问题**区域显示与您的数据上下文相关的预生成问题。这些建议由系统根据您的资产层次结构和采集数据生成。

点击"推荐问题"旁边的**刷新图标**可加载一组新的建议。

点击任意建议即可直接使用——问题将被放入输入框并自动发送。

## 8.6.6 小T 如何回答

当您提交问题时，小T 使用适当的 SQL 查询您的 TDengine 数据，检索结果后，返回自然语言答案。对于数据问题，回答包含计算出的数值。对于分析性问题，可能包含图表、表格或叙述性解释。

所有答案都基于您的实际数据——小T 不会捏造数值。

## 8.6.7 工具执行前确认

AI 问答还可以通过工具创建面板、更新面板或创建分析。在**个人设置 → Agent** 中开启**执行前确认**后，需要确认的写操作会暂停，并在对话中显示确认卡片；只读查询无需确认。该开关默认关闭，切换后自动保存，从下一次任务生效，详见[个人设置](../14-administration/08-profile-settings.md#1485-agent)。

### 8.6.7.1 确认卡片的操作

确认卡片显示操作名称、工具名称和参数详情。展开**详情**核对目标资源与参数后，可以选择以下操作：

| 操作 | 说明 |
|---|---|
| **执行** | 使用当前参数执行本次操作，然后继续任务 |
| **编辑参数** | 打开可编辑参数表单，修改后点击**执行**，使用修改后的参数执行；关闭编辑对话框不会执行操作 |
| **跳过** | 不执行本次操作，将跳过结果交回 AI 继续处理任务 |
| **取消任务** | 拒绝本次操作并停止当前任务；已完成的操作不会回滚 |

确认过期后，卡片操作不可用，需要重新发起请求。修改个人确认开关不会替代对已有卡片的选择；刷新或重新打开会话后，仍有效的待确认操作可在恢复后继续处理。

用量统计仅显示模型实际返回的 Token 用量；模型未返回用量时，不会以零代替未知用量。模型明确返回的零用量会按零保留。任务中途失败或暂停前已经返回的用量会保留；只有确认回执、没有新增模型调用的操作不会产生额外 Token 用量。

### 8.6.7.2 AI 问答调用用户自定义 MCP 服务

此处的“用户自定义 MCP 服务”是指在 IDMP 中配置并启用、供 AI 问答调用的 MCP 服务。例如，连接企业工单系统后，AI 问答可以调用该服务的“查询工单”和“创建工单”工具。此时 **IDMP 是 MCP 客户端，工单系统是 MCP 服务端**。该功能适用于 AI 问答通过 IDMP 发起的调用；其他客户端直接调用该 MCP 服务时，不受 IDMP 个人确认开关影响。**IM 暂时不支持执行前确认**。

接入步骤如下：

1. 管理员在[基础库 → Agentic AI → MCP 模板](../13-libraries/05-agentic-ai.md#1352-mcp-模板)中配置并启用服务模板；当前用户在[个人设置 → Agent](../14-administration/08-profile-settings.md#1485-agent) 中填写连接所需的变量，确保对应工具可用。
2. 在 MCP 服务端的工具定义中设置 `annotations.readOnlyHint` 和 `annotations.destructiveHint`。IDMP 通过 `tools/list` 读取这些声明；它们不是工具的输入参数，也不是在聊天中让 AI 判断的设置。
3. 在**个人设置 → Agent** 中开启**执行前确认**，随后发起新的 AI 问答任务。
4. 当 AI 选择调用某个工具时，IDMP 根据下表判断是否暂停。需要确认时，对话中先显示确认卡片，MCP 服务端此时尚未收到该工具的执行请求；点击**执行**后才发送 `tools/call`。

以下为**确认开关已开启**时的完整判断表。“未填写”表示工具声明中不存在该字段。

| `readOnlyHint` | `destructiveHint` | AI 问答的行为 |
|---|---|---|
| `true` | `false` | 直接调用，不显示确认卡片 |
| `true` | 未填写 | 直接调用，不显示确认卡片 |
| `true` | `true` | 显示确认卡片；该组合声明相互矛盾，应修正服务端定义 |
| `false` | `false` | 显示确认卡片，新增操作同样需要确认 |
| `false` | `true` | 显示确认卡片 |
| `false` | 未填写 | 显示确认卡片 |
| 未填写 | `false` | 显示确认卡片 |
| 未填写 | `true` | 显示确认卡片 |
| 未填写 | 未填写 | 显示确认卡片 |

**关闭确认开关后，新任务中的上述工具均直接调用。** 开关控制是否等待用户确认，不替代工具原有的权限和参数校验。

例如，工单服务的 `tools/list` 响应可以包含以下两个工具定义。实际 SDK 注册工具时，应将 `annotations` 设置在工具定义上，与 `inputSchema` 同级。

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "create_work_order",
        "description": "创建工单",
        "inputSchema": {
          "type": "object",
          "properties": {
            "title": { "type": "string" }
          },
          "required": ["title"]
        },
        "annotations": {
          "readOnlyHint": false,
          "destructiveHint": false
        }
      },
      {
        "name": "get_work_order",
        "description": "查询工单",
        "inputSchema": {
          "type": "object",
          "properties": {
            "id": { "type": "string" }
          },
          "required": ["id"]
        },
        "annotations": {
          "readOnlyHint": true,
          "destructiveHint": false
        }
      }
    ]
  }
}
```

开启确认后，提问“创建一个标题为‘检查 em-3 电压’的工单”，当 AI 选择 `create_work_order` 时，IDMP 先显示确认卡片，点击**执行**后才创建工单。提问“查询工单 WO-123”，当 AI 选择 `get_work_order` 时，IDMP 直接查询并返回结果，不显示确认卡片。

`readOnlyHint: false` 表示工具可能修改数据，因此即使 `destructiveHint: false` 表示仅新增数据，也仍需要确认。真正只读的查询工具应声明为 `readOnlyHint: true`、`destructiveHint: false`。这些字段属于 [MCP 标准工具声明](https://modelcontextprotocol.io/specification/2025-06-18/schema#toolannotations)；是否显示确认卡片是 IDMP 的处理规则，由代码决定，AI 不能跳过。服务端应按工具的实际行为声明这些提示字段。

这里的“只读”来自 **MCP 服务端的声明**。IDMP 使用该声明决定是否确认，不会独立验证工具实现是否真的没有写操作。因此，应仅连接可信的 MCP 服务，并由服务端维护者如实声明工具行为。例如，`get_work_order` 只有在实现确实只查询工单时才应声明只读；如果它还会更新工单状态，应声明 `readOnlyHint: false`，以便开启确认后先显示卡片。

**普通确认无需额外开发确认接口，也无需提供 `validate_*` 工具或 `x-idmp-confirmation-policy`。** 这些额外约定仅用于下节介绍的参数编辑能力。

### 8.6.7.3 在确认卡片中编辑参数

目前仅支持编辑下表中的字段；原始工具参数中必须已存在该字段，且值为字符串。不能通过编辑新增缺失字段，也不能编辑任意对象或数组。

| 工具 | 可编辑字段 | 限制 |
|---|---|---|
| 创建面板（`create_panel`） | 面板名称（`config.name`） | 1–250 个 Unicode 字符，不能全部为空白 |
| 创建分析（`create_analysis`） | 分析名称（`config.name`） | 1–250 个 Unicode 字符，不能全部为空白 |
| 创建分析（`create_analysis`） | 描述（`config.description`） | 最多 2048 个 Unicode 字符，允许空字符串 |
| 其他工具（包括更新面板） | 不支持编辑 | 可以核对参数后选择执行、跳过或取消任务 |

SQL、表达式、告警阈值、计算周期、目标元素及资源 ID 等参数受保护，不能在确认卡片中修改。需要调整这些参数时，请取消当前任务，重新说明需求。敏感字段不会提供明文编辑；参数不合法时无法提交。工具没有可编辑参数或参数加载失败时，界面会显示相应提示。

用户自定义 MCP 工具出现确认卡片，并不表示支持编辑参数。例如，上节的 `create_work_order` 可以执行、跳过或取消，但不能在卡片中修改工单标题。

如需让自定义 MCP 的面板或分析创建工具支持编辑，服务端还需适配 IDMP 的额外约定：在工具的 `inputSchema` 中声明 `x-idmp-confirmation-policy`（面板为 `idmp-create-panel-v1`，分析为 `idmp-create-analysis-v1`），采用上表的参数结构，并在同一 MCP 连接中提供对应的只读校验工具（`create_panel` 对应 `validate_panel`，`create_analysis` 对应 `validate_analysis`）。工具与校验工具必须均可用，修改后的参数必须通过校验，受保护参数必须保持不变。这些是 **IDMP 自定义的参数编辑约定，不属于 MCP 标准**；仅使用相同工具名或定义参数结构不会启用编辑能力，也不影响普通执行前确认。

例如，输入“给 em-3 创建分析，每五分钟计算最大电压，超过 240 就告警”。当 AI 准备调用创建分析工具时，开启确认的用户会先看到确认卡片，可以核对周期和阈值，并按上述限制修改名称或描述后再执行；关闭确认时，工具按现有规则直接执行。创建成功后，可通过回复中的分析链接打开对应资源。
