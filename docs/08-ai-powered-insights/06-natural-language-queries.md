# 8.6 AI 助手

**AI 助手**（名为**小T**）是元素浏览器浏览与详情页面工作区右侧常驻的自然语言对话面板，用于查询和分析当前元素与页面的数据。无需编写 TDengine SQL 或在资产层次结构中逐层查找，即可直接提问，例如"em-1 昨天的峰值电压是多少？"，并获得基于实际数据的答案。

## 8.6.1 打开 AI 助手

在元素浏览器中选中元素后，AI 助手默认显示在工作区右侧。若已收起，可点击上下文标签栏最右侧的 **AI 助手开关**重新展开；AI 助手标题栏左侧的按钮用于收起或展开中间工作区。AI 助手的展开/收起状态会跨刷新保留。

- AI 助手仅在 AI 服务可用时显示。AI 连接不可用时，应由管理员配置有效的 [AI 连接](./01-connecting-to-llm.md)；AI 许可证过期或权限不足时，也需联系管理员处理。
- 可拖动 AI 助手左侧的分隔条调整宽度，范围为 320 像素至浏览器窗口宽度的 60%；宽度设置会保留到下次访问。
- 顶部导航栏不提供独立的 AI 助手入口，AI 助手随元素浏览器加载。
- 面板、元素和仪表板的全屏编辑页面不显示 AI 助手。
- 从专家中心点击**召唤**或从定时任务通知打开结果时，会进入独立的完整 AI 对话页面；该页面包含左侧历史栏，布局与右侧 AI 助手不同。

## 8.6.2 界面布局

AI 助手面板由标题栏、对话区和输入区组成：

**标题栏。** 显示 **AI 助手**；存在活动会话时，标题后附加会话名称，名称过长时自动省略。标题栏右侧提供两个入口：**定时任务**（闹钟图标）和**历史记录**（列表图标）。

**对话区。** 显示问候语、历史消息和流式生成的回答。欢迎语为 *"嗨，我是小T，有什么可以帮到您？"*。

**输入区。** 包含以下元素：

- **上下文标签**：当前元素、手动加入的元素和当前页面，可单独关闭（见 [8.6.6 上下文与多元素分析](#866-上下文与多元素分析)）
- 文本输入框；面板、实时分析、事件、属性、仪表板和关联元素页面会显示与页面相关的提示文案
- 输入框左下方的**专家**按钮、**技能**入口（输入 `/` 可唤起技能列表）和**深度思考**切换按钮
- 输入框右侧的**麦克风**按钮，支持语音输入
- 存在会话时提供的**开启新对话**按钮，可开始空白会话
- 新对话时显示的**推荐问题**区域（位于输入框上方）

**浮动边栏。** 历史记录和定时任务以浮动边栏显示在对话区右侧，左侧边界可拖拽调整宽度，底边停在输入框上沿。两个边栏互斥，同一时间只能打开一个。AI Function 执行会话与面板解读会话也使用同一片对话区，打开其中一个会退出另一个。

## 8.6.3 提问

需要在未来时间或按日、按周重复执行只读分析时，可在会话中创建 [AI 定时任务](./13-scheduled-tasks.md)。定时任务需要单独配置后台授权，并在创建或修改时确认计划与时区。

在输入框中输入问题。按 **Enter** 发送，或按 **Shift+Enter** 换行而不发送。

也可以按**麦克风**按钮使用语音输入。说出问题后，系统将其转录到输入框中。

## 8.6.4 深度思考模式

**深度思考**切换开关将查询路由到深度思考模型（在连接管理中配置）。对于需要扩展推理的复杂多步问题，请使用此模式——例如，跨时间窗口关联多个属性，或请求根因假设。关于数据值的标准问题无需深度思考模式。

## 8.6.5 推荐问题

**推荐问题**区域按页面类型生成问题，并以当前元素和元素模板作为上下文。面板、实时分析、事件和仪表板页面会分别推荐对应类型的问题。

- 切换左树中选中的元素时，推荐问题**不会自动刷新**，当前列表保持不变。
- 只有推荐类型发生变化时才会自动重新生成（例如从面板页切换到实时分析页）；通用页内部的页面切换会沿用当前列表。
- 点击推荐问题标题旁的**刷新**图标（提示文案为"换一换"），可主动按当前元素和页面重新请求一组问题；主动刷新会跳过缓存，确保结果与当前上下文一致。
- 点击任意建议即可直接使用，问题将被放入输入框并自动发送。

## 8.6.6 上下文与多元素分析

AI 助手在发送问题时会一并发送当前上下文。输入框上方的上下文标签显示当前生效的上下文：

- **元素标签**：左树中选中的元素。
- **手动加入的元素标签**：从元素树加入的其他元素，用于多元素对比或关联分析。
- **页面标签**：当前页面名称，例如"属性""面板""仪表板"。

点击元素标签或页面标签上的关闭按钮，当前元素或页面的后续提问将不再包含该部分上下文；切换元素或页面后，已关闭的标签会恢复。点击手动加入的元素标签上的关闭按钮，会将该元素从上下文中移除；如需再次使用，需从元素树重新添加。

要把其他元素加入上下文，可在左侧元素树中悬停任意元素、收藏元素或分组中的元素，点击行内最左侧的**添加到 AI 助手上下文**按钮。加入后 AI 助手自动展开，并在输入框上方显示该元素的标签；再次点击同一按钮可移除。最多可加入 5 个元素，输入框上方最多同时展示 3 个上下文标签，其余元素仍会随请求发送；未显示的标签无法在输入框中关闭，需通过元素树中的按钮移除对应元素。

手动加入的元素在当前浏览器会话内跨页面保留；刷新页面后清空。

## 8.6.7 历史记录

点击 AI 助手标题栏右侧的**历史记录**按钮（列表图标），打开历史记录浮动边栏。边栏包含：

- 会话筛选（**全部会话** / **有定时任务的会话**）与刷新按钮。
- 搜索框，可在当前已加载的会话摘要中按标题或首个问题过滤。
- 按日期分组的会话列表，点击条目即可在对话区打开该会话。
- 底部分页控件，可翻页查看更多会话。

再次点击历史记录按钮、点击边栏以外的区域或按 **Esc** 键均可关闭边栏。打开历史记录时，当前打开的 AI Functions 会话或面板解读会话会关闭；历史记录与定时任务边栏互斥。

当对话中出现待确认卡片时，历史记录浮动边栏会临时收起，避免遮挡确认按钮；卡片处理完成后自动恢复。

## 8.6.8 定时任务

点击 AI 助手标题栏右侧的**定时任务**按钮（闹钟图标），打开定时任务浮动边栏。边栏提供**定时任务**、**全部执行记录**和**后台授权**三个页签，用于创建和管理定时任务、查看执行记录以及配置后台授权。

打开定时任务边栏时，当前打开的 AI Functions 会话或面板解读会话会关闭。在边栏中选择一条运行结果后，边栏关闭并在对话区打开对应结果。再次点击闹钟按钮、点击边栏以外的区域或按 **Esc** 键均可关闭边栏。与历史记录不同，出现待确认卡片时定时任务边栏不会自动收起，需要手动关闭。定时任务的创建、确认和执行规则参见 [AI 定时任务](./13-scheduled-tasks.md)。

## 8.6.9 小T 如何回答

当您提交问题时，小T 使用适当的 SQL 查询您的 TDengine 数据，检索结果后，返回自然语言答案。对于数据问题，回答包含计算出的数值。对于分析性问题，可能包含图表、表格或叙述性解释。

所有答案都基于您的实际数据——小T 不会捏造数值。

## 8.6.10 工具执行前确认

AI 助手还可以通过工具创建面板、更新面板或创建分析。在**个人设置 → Agent** 中开启**执行前确认**后，需要确认的写操作会暂停，并在对话中显示确认卡片；只读查询无需确认。该开关默认关闭，切换后自动保存，从下一次任务生效，详见[个人设置](../14-administration/08-profile-settings.md#1485-agent)。

### 8.6.10.1 确认卡片的操作

确认卡片显示操作名称、工具名称和参数详情。展开**详情**核对目标资源与参数后，可以选择以下操作：

| 操作 | 说明 |
|---|---|
| **执行** | 使用当前参数执行本次操作，然后继续任务 |
| **编辑参数** | 打开可编辑参数表单，修改后点击**执行**，使用修改后的参数执行；关闭编辑对话框不会执行操作 |
| **跳过** | 不执行本次操作，将跳过结果交回 AI 继续处理任务 |
| **取消任务** | 拒绝本次操作并停止当前任务；已完成的操作不会回滚 |

确认过期后，卡片操作不可用，需要重新发起请求。修改个人确认开关不会替代对已有卡片的选择；刷新或重新打开会话后，仍有效的待确认操作可在恢复后继续处理。

用量统计仅显示模型实际返回的 Token 用量；模型未返回用量时，不会以零代替未知用量。模型明确返回的零用量会按零保留。任务中途失败或暂停前已经返回的用量会保留；只有确认回执、没有新增模型调用的操作不会产生额外 Token 用量。

### 8.6.10.2 AI 助手调用用户自定义 MCP 服务

此处的“用户自定义 MCP 服务”是指在 IDMP 中配置并启用、供 AI 助手调用的 MCP 服务。例如，连接企业工单系统后，AI 助手可以调用该服务的“查询工单”和“创建工单”工具。此时 **IDMP 是 MCP 客户端，工单系统是 MCP 服务端**。该功能适用于 AI 助手通过 IDMP 发起的调用；其他客户端直接调用该 MCP 服务时，不受 IDMP 个人确认开关影响。**IM 暂时不支持执行前确认**。

接入步骤如下：

1. 管理员在[基础库 → Agentic AI → MCP 模板](../13-libraries/05-agentic-ai.md#1352-mcp-模板)中配置并启用服务模板；当前用户在[个人设置 → Agent](../14-administration/08-profile-settings.md#1485-agent) 中填写连接所需的变量，确保对应工具可用。
2. 在 MCP 服务端的工具定义中设置 `annotations.readOnlyHint` 和 `annotations.destructiveHint`。IDMP 通过 `tools/list` 读取这些声明；它们不是工具的输入参数，也不是在聊天中让 AI 判断的设置。
3. 在**个人设置 → Agent** 中开启**执行前确认**，随后发起新的 AI 助手任务。
4. 当 AI 选择调用某个工具时，IDMP 根据下表判断是否暂停。需要确认时，对话中先显示确认卡片，MCP 服务端此时尚未收到该工具的执行请求；点击**执行**后才发送 `tools/call`。

以下为**确认开关已开启**时的完整判断表。“未填写”表示工具声明中不存在该字段。

| `readOnlyHint` | `destructiveHint` | AI 助手的行为 |
|---|---|---|
| `true` | `false` | 直接调用，不显示确认卡片 |
| `true` | 未填写 | 直接调用，不显示确认卡片 |
| `true` | `true` | 显示确认卡片；该组合声明相互矛盾，应修正服务端定义 |
| `false` | `false` | 显示确认卡片，新增操作同样需要确认 |
| `false` | `true` | 显示确认卡片 |
| `false` | 未填写 | 显示确认卡片 |
| 未填写 | `false` | 显示确认卡片 |
| 未填写 | `true` | 显示确认卡片 |
| 未填写 | 未填写 | 显示确认卡片 |

**关闭确认开关后，新任务中的上述工具均直接调用。** 开关控制是否等待用户确认，不替代工具原有的权限和参数校验。

例如，工单服务的 `tools/list` 响应可以包含以下两个工具定义。实际 SDK 注册工具时，应将 `annotations` 设置在工具定义上，与 `inputSchema` 同级。

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "create_work_order",
        "description": "创建工单",
        "inputSchema": {
          "type": "object",
          "properties": {
            "title": { "type": "string" }
          },
          "required": ["title"]
        },
        "annotations": {
          "readOnlyHint": false,
          "destructiveHint": false
        }
      },
      {
        "name": "get_work_order",
        "description": "查询工单",
        "inputSchema": {
          "type": "object",
          "properties": {
            "id": { "type": "string" }
          },
          "required": ["id"]
        },
        "annotations": {
          "readOnlyHint": true,
          "destructiveHint": false
        }
      }
    ]
  }
}
```

开启确认后，提问“创建一个标题为‘检查 em-3 电压’的工单”，当 AI 选择 `create_work_order` 时，IDMP 先显示确认卡片，点击**执行**后才创建工单。提问“查询工单 WO-123”，当 AI 选择 `get_work_order` 时，IDMP 直接查询并返回结果，不显示确认卡片。

`readOnlyHint: false` 表示工具可能修改数据，因此即使 `destructiveHint: false` 表示仅新增数据，也仍需要确认。真正只读的查询工具应声明为 `readOnlyHint: true`、`destructiveHint: false`。这些字段属于 [MCP 标准工具声明](https://modelcontextprotocol.io/specification/2025-06-18/schema#toolannotations)；是否显示确认卡片是 IDMP 的处理规则，由代码决定，AI 不能跳过。服务端应按工具的实际行为声明这些提示字段。

这里的“只读”来自 **MCP 服务端的声明**。IDMP 使用该声明决定是否确认，不会独立验证工具实现是否真的没有写操作。因此，应仅连接可信的 MCP 服务，并由服务端维护者如实声明工具行为。例如，`get_work_order` 只有在实现确实只查询工单时才应声明只读；如果它还会更新工单状态，应声明 `readOnlyHint: false`，以便开启确认后先显示卡片。

**普通确认无需额外开发确认接口，也无需提供 `validate_*` 工具或 `x-idmp-confirmation-policy`。** 这些额外约定仅用于下节介绍的参数编辑能力。

### 8.6.10.3 在确认卡片中编辑参数

目前仅支持编辑下表中的字段；原始工具参数中必须已存在该字段，且值为字符串。不能通过编辑新增缺失字段，也不能编辑任意对象或数组。

| 工具 | 可编辑字段 | 限制 |
|---|---|---|
| 创建面板（`create_panel`） | 面板名称（`config.name`） | 1–250 个 Unicode 字符，不能全部为空白 |
| 创建分析（`create_analysis`） | 分析名称（`config.name`） | 1–250 个 Unicode 字符，不能全部为空白 |
| 创建分析（`create_analysis`） | 描述（`config.description`） | 最多 2048 个 Unicode 字符，允许空字符串 |
| 其他工具（包括更新面板） | 不支持编辑 | 可以核对参数后选择执行、跳过或取消任务 |

SQL、表达式、告警阈值、计算周期、目标元素及资源 ID 等参数受保护，不能在确认卡片中修改。需要调整这些参数时，请取消当前任务，重新说明需求。敏感字段不会提供明文编辑；参数不合法时无法提交。工具没有可编辑参数或参数加载失败时，界面会显示相应提示。

用户自定义 MCP 工具出现确认卡片，并不表示支持编辑参数。例如，上节的 `create_work_order` 可以执行、跳过或取消，但不能在卡片中修改工单标题。

如需让自定义 MCP 的面板或分析创建工具支持编辑，服务端还需适配 IDMP 的额外约定：在工具的 `inputSchema` 中声明 `x-idmp-confirmation-policy`（面板为 `idmp-create-panel-v1`，分析为 `idmp-create-analysis-v1`），采用上表的参数结构，并在同一 MCP 连接中提供对应的只读校验工具（`create_panel` 对应 `validate_panel`，`create_analysis` 对应 `validate_analysis`）。工具与校验工具必须均可用，修改后的参数必须通过校验，受保护参数必须保持不变。这些是 **IDMP 自定义的参数编辑约定，不属于 MCP 标准**；仅使用相同工具名或定义参数结构不会启用编辑能力，也不影响普通执行前确认。

例如，输入“给 em-3 创建分析，每五分钟计算最大电压，超过 240 就告警”。当 AI 准备调用创建分析工具时，开启确认的用户会先看到确认卡片，可以核对周期和阈值，并按上述限制修改名称或描述后再执行；关闭确认时，工具按现有规则直接执行。创建成功后，可通过回复中的分析链接打开对应资源。
