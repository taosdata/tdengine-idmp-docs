# 8.13 专家模式

**专家模式**让 AI 问答从「一个通用助手」变成「一支各有所长的专家团队」。您针对不同任务选择对应领域的专家，这位专家以固定的人设、方法与能力来回答——例如让「根因分析」专家排查设备异常，让「报告生成」专家整理分析报告。

平台内置 13 位专家，覆盖数据查询、面板创建、异常检测、根因分析、趋势预测等常见工业数据分析场景；您也可以在专家中心创建自己的专家，绑定特定 Skill，形成团队的专属助手。

## 8.13.1 什么是专家

一位**专家**是「人设 + 方法论 + 工具链」的声明式打包：

- **人设**：专家以什么身份和口径回答——身份、职责、专业视角与回答风格。
- **方法论**：专家完成任务遵循的流程与领域知识，表现为其绑定的一组 Skill。
- **工具链**：专家可用的工具集。

将一位专家与 AI 问答会话绑定后，每一轮提问都会以该专家的视角与能力作答。

## 8.13.2 专家中心

**专家中心**是管理与配置专家的页面，路径为**资源库 → Agentic AI → 专家中心**。在这里浏览内置专家、查看详情，并创建和管理自己的专家。

### 8.13.2.1 浏览与筛选

- 顶部搜索框可按名称、描述或领域过滤。
- **来源**筛选分为**内置**（平台内置，不可修改删除）、**定制**与**用户**（您与团队创建的）。

### 8.13.2.2 查看专家详情

点击卡片上的**查看**进入详情页，可执行**编辑**、**克隆**、**删除**与**召唤**。详情展示该专家的**绑定 Skill**与**工具链**，以及模型与默认模式等元信息。

### 8.13.2.3 新建自定义专家

在专家中心工具栏点击**新建**，填写以下字段：

- **名称**：专家的英文标识，创建后不可修改（需匹配 `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$`）。
- **展示名**：显示在卡片、标签行与会话历史中的名称。
- **领域**：擅长领域标签。
- **描述**：一句话能力介绍。
- **绑定 Skill**：从平台 Skill 清单中选择该专家采用的方法集。
- **工具链**：选择该专家可用的工具。
- **人设正文**：用自然语言撰写专家的身份、职责与回答风格。

保存后即出现在**用户**来源的列表中，可在 AI 问答中召唤使用。更新与删除同样在专家中心完成；删除用户专家不会影响既有会话的历史消息。

## 8.13.3 在 AI 问答中使用专家

在 **AI 问答**（8.6）中输入框上方有一行**专家标签**，每位专家一个标签。点击任意标签即在当前会话中选定该专家；再点击其他标签即可切换。

- 输入框左下方还有一个紧凑的**专家**按钮，点击会打开专家选择浮层（含搜索），并可在浮层底部**退出专家**，回到通用助手。
- 选定专家后，对应标签高亮，专家按钮上显示所选专家名称。
- **切换专家会开启一条新会话**——原会话历史中模型已按前一位专家的身份作答，因此切换后从新会话的第一轮起以新专家身份回复；原会话保留在左侧对话历史中。
- 刷新页面后，当前会话与其专家绑定都会保持。

**推荐问题、重新生成、编辑重发**都会沿用当前会话绑定的专家。

:::tip
若所选专家已不可用（例如已被删除），本轮将按通用助手继续，并弹出提示。
:::

## 8.13.4 内置专家一览

| 专家 | 领域 | 典型用途 |
|------|------|----------|
| 数据查询 | 数据查询 | 把自然语言问题翻译成对设备属性与时序数据的精确查询 |
| 面板创建 | 可视化 | 用自然语言描述面板并由 AI 构建 |
| 实时分析 | 实时分析 | 面向实时数据的分析与取数 |
| 告警配置 | 告警 | 配置与维护告警规则 |
| 异常检测 | 异常检测 | 检测时序数据中的异常模式 |
| 趋势预测 | 趋势预测 | 基于历史数据的时序预测 |
| 根因分析 | 设备诊断 | 对事件与告警做证据受限的因果溯源与结构化解释 |
| 事件查询 | 事件 | 检索与解读历史事件 |
| 对比分析 | 对比分析 | 多对象、多时段的对比分析 |
| 健康评估 | 设备健康 | 评估设备健康度并输出评分卡 |
| 指标计算 | 指标 | 计算与聚合自定义指标 |
| 报告生成 | 报告 | 把数据与分析结论组装成结构化报告 |
| 面板解读 | 面板洞察 | 解读面板内容并给出可执行结论 |

> 您创建的**用户**专家会与内置专家一同出现在标签行中。

## 8.13.5 使用建议

- 按任务类型选专家：查询数据用**数据查询**，排查设备异常用**根因分析**，出报告用**报告生成**。
- 专家绑定的 Skill 决定了其方法论，人设决定了回答口径——需要团队统一方法时，为团队创建专属专家。
- 创建专家时，**人设正文**写得越具体（职责、边界、输出格式），回答越贴合预期。
