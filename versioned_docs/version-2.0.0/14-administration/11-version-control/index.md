# 14.11 版本控制

TDengine IDMP 内置了基于 Git 的版本控制系统，将资产模型的所有元数据
（元素、模板、仪表板、面板、分析、连接、库等）以 JSON 文件的形式
持久化到 Git 仓库中，让用户对每一次修改都可以**追踪**、**审查**和**回滚**。

## 为什么需要版本控制？

在工业场景（如制药、能源）中，资产模型的变更需要严格的流程控制：

- **变更追溯**：谁在什么时间、为什么修改了某个属性？
- **审批流程**：关键变更需要经过 Reviewer 审核才能生效
- **回滚能力**：误操作后能快速恢复到任意历史版本
- **合规要求**：满足 FDA 21 CFR Part 11、EU Annex 11 等监管要求

IDMP 选择 Git 作为版本控制引擎，因为它天然提供完整历史、
diff 对比、分支管理和合并能力，是业界最成熟的版本控制方案。

## 功能概览

| 功能 | 说明 |
|------|------|
| **变更追踪** | 右上角徽标实时显示未提交变更数，一键打开变更列表 |
| **Check-In（签入）** | 填写变更原因后提交改动，生成 Git commit |
| **Undo（撤销）** | 撤销未提交的改动，恢复到上一个版本 |
| **Diff 对比** | 查看任意变更的 HEAD 版本与工作区版本的差异 |
| **个人工作空间** | 审核模式下自动创建个人分支，隔离未审核的修改 |
| **Pull Request 审核** | 在 Review Required 模式下，变更需通过 MR/PR 审核 |
| **电子签名** | 支持 GPG 密钥对提交进行电子签名 |
| **版本发布** | 管理已发布版本，支持自动发布和手动发布 |

## 修改模式

IDMP 支持三种修改模式，适应不同行业的合规要求：

- **Version Track（版本追踪）**：所有用户共享 main 分支，修改直接提交
- **Review Required（审核必需）**：修改必须通过 MR/PR 审核后才能合入
- **E-Signature（电子签名）**：在 Review Required 基础上增加 GPG 电子签名

## 发布模式

- **自动推送（Auto-Push）**：合并后自动更新运行系统
- **人工管理（Manual）**：管理员决定何时发布哪个版本
