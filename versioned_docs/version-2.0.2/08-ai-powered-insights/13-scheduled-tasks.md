# 8.13 AI 定时任务

AI 定时任务按约定时间在后台执行只读 AI 分析，并将每次执行保存到 AI 问答历史。适用于每日设备巡检摘要、每周能耗分析，以及一段时间后的检查提醒。创建后无需保持浏览器打开。

本功能与[定时报表](../04-visualization/06-scheduled-reports.md)不同：定时报表定期导出可视化内容；AI 定时任务执行自然语言描述的查询与分析。

## 8.13.1 使用前准备

AI 服务默认提供定时任务能力，无需配置功能开关。管理员需配置可用的[大语言模型连接](./01-connecting-to-llm.md)，并授予当前用户 AI 问答访问权限。用户只能管理本人的任务，无需额外的定时任务管理权限。未显示入口或提示无法加载时，应先联系管理员检查 AI 问答权限与服务状态。

:::info 持久化配置

将 `IDMP_DATA_PATH` 指向持久化数据目录。首次启动自动生成加密主密钥，保存在 `ai_scheduled_tasks/.credential-key`，后续启动复用；任务及加密凭据也保存在 `ai_scheduled_tasks/` 下，应完整备份和恢复此目录。已有部署通过 `IDMP_SCHEDULED_TASKS_KEY` 显式配置的 Base64 编码 32 字节主密钥继续使用原值，不能丢失或随意更换。当前仅支持单实例调度，任务管理和聊天确认请求应路由到同一个实例；通知中的 Web 链接使用 `IDMP_FRONTEND_URL`。

自动生成的主密钥以原始字节保存，文件创建权限为 `0600`。应限制整个数据目录及备份的访问权限；同时取得主密钥和凭据文件即可解密凭据。

管理员应先停止 AI 定时任务服务，再以同一备份时点保存 AI 服务持久化数据、系统元数据库和原主密钥。系统长期保留少量任务、执行和会话标识，以及结果已删除的状态，用于防止重复执行、保持结果只读，并避免已删除结果重新出现；这些信息不含报告内容或凭据。完整执行记录受容量限制，但上述标识和状态占用的磁盘空间会随历史会话增长，总存储并非固定大小。不要手动删除文件释放空间。

:::

后台执行使用本人的 IDMP API Key，继承该用户当前的权限和数据范围，不使用浏览器登录令牌。

1. 打开顶部导航栏的 **AI 问答**，点击左侧历史工具栏中的小闹钟图标。对话框提供**定时任务**、**全部执行记录**和**后台授权**三个页签，切换到**后台授权**。
2. 在**本人的 IDMP API Key** 下拉框中选择现有 Key。列表显示名称、掩码和到期时间，已过期的 Key 不可选择。
3. 如果没有合适的 Key，点击**新增 API Key**，在现有[个人设置](../14-administration/08-profile-settings.md#1483-api-key)中创建，再关闭个人设置，返回选择新 Key。无需复制或粘贴密钥。
4. 点击**保存授权**。新建 Key 不会自动授权，需明确选择并保存。
5. 核对页面常驻提示中的 Key 名称、到期时间，并确认授权状态为“有效”，随后关闭对话框。

浏览器只提交所选 Key 的 ID，服务端核对本人归属和有效性后加密保存密钥；不能选择他人的 Key。当前账户的定时任务共用该授权。页面提示中的共用任务数仅统计已启用或待授权的任务，不包含已暂停或已完成的任务，也不表示此刻正在执行的数量。更新授权不会自动恢复任务或重跑旧记录，保存失败也不会覆盖原授权。

系统启用审计且要求提供操作原因时，保存授权、暂停、恢复、停止任务和删除执行记录会弹出系统统一的原因输入框。填写原因并确认后才会发送请求，取消则不执行操作。管理员可在**系统日志**中按 **AI 定时任务**资源类型查询这些操作；授权密钥和生成报告不写入操作快照。

## 8.13.2 用自然语言创建并确认

在普通 AI 问答会话中描述执行内容、时间、时区和通知方式。应提供明确的设备、属性、查询范围和输出要求；重要上下文应写入任务描述，不能依赖执行时重新读取完整来源会话。

例如，在已完成后台授权后输入：

```text
创建一个定时只读任务，标题为“设备巡检摘要”。
每周一至周五 09:15，使用 Asia/Shanghai 时区执行。
查询系统概览并汇总可获取的信息；无数据时明确说明，不推测数值。
结果仅保存到 Web 历史，不发送 IM 通知。请展示配置供我确认，不要立即执行。
```

1. 发送请求，等待系统显示 `create_scheduled_task` 确认卡片。
2. 展开**详情**，核对标题、完整执行内容、周期、时间、时区和渠道。
3. 勾选**我已确认使用时区：Asia/Shanghai**。时区应为实际需要的 IANA 标识，例如 `Asia/Shanghai` 或 `Europe/Berlin`，不应仅填写“北京时间”或 `UTC+8`。
4. 点击**执行**。只有确认成功后任务才会创建；收到确认卡片不表示任务已生效。
5. 打开**定时任务**，点击任务标题，核对**常规**页签中的计划和**下次执行**。

如配置不符合预期，应取消本次操作，在会话中描述修正内容，再核对新的确认卡片。未指定时区时，Web 请求使用浏览器提供的 IANA 时区，仍需在确认卡片中明确确认；无法获取浏览器时区时应先补充时区。定时任务创建和修改始终要求确认，不受个人“执行前确认”开关关闭的影响。第一版建议从 Web 创建，不能在 IM 中完成此确认流程。

### 8.13.2.1 支持的时间计划

创建和修改时均可使用下列计划，最终以确认卡片和任务详情中的配置为准。

| 计划 | 自然语言示例 | 说明 |
|---|---|---|
| 指定时间执行一次 | 明天 15:00 检查设备状态，时区 Asia/Shanghai | 必须是未来时间 |
| 延迟后执行一次 | 确认后 2 分钟检查系统概览，时区 Asia/Shanghai | 从点击确认时计算，随后保存为固定执行时间 |
| 每天 | 每天 08:30 生成运行摘要，时区 Asia/Shanghai | 按任务时区执行 |
| 每周指定日期 | 每周一至周五 09:15 生成巡检摘要，时区 Asia/Shanghai | “工作日”仅表示周一至周五，不处理法定节假日或调休 |

当前不支持每隔若干分钟循环执行、月度计划或节假日日历。定时任务仅执行只读查询和分析，不用于定期创建面板、修改配置等写操作。

### 8.13.2.2 结果通知

每次执行均以 Web 历史作为结果入口。还可在请求中指定已启用、且已与当前账户绑定的 IM 渠道，例如“同时通过飞书通知本人”；绑定方法参见 [IM 多通道集成](./12-im-channels.md)。确认前需检查渠道是否正确。

创建或修改任务时，系统检查所选渠道是否正在运行、是否与本人账户绑定；检查失败则不保存本次配置。收件人来自当前账户的渠道绑定，不由任务描述指定。发送通知前会再次检查渠道和绑定；若渠道之后被停用或解绑，执行记录会显示明确的通知失败原因，已生成的 Web 结果仍可查看。

管理员将渠道切换到其他企业或机器人，或删除渠道配置时，该渠道已有的用户绑定和未使用的绑定验证码将失效，尚未完成的操作确认也不能继续使用旧绑定。用户需要与新机器人重新绑定，定时任务才可恢复该渠道的通知；其他渠道的绑定不受影响。同一机器人仅更新密钥时保留绑定。Slack 更换机器人令牌时无法可靠确认是否仍为同一机器人，因此也需要重新绑定；仅更新 Slack 应用令牌时保留绑定。渠道配置更改后需重新启动该渠道；系统不会将旧机器人的接收人标识交给新机器人发送。

定时任务通知支持飞书、Telegram、钉钉、Slack 和企业微信。**个人微信不支持定时任务主动通知**：个人微信只能在用户发起的会话中回复，无法在任务执行后主动推送消息。因此创建或修改定时任务时不能选择个人微信，确认卡会提示该渠道不可用并禁止执行；即使在个人微信中发起请求，也需要改选其他已绑定渠道或仅保存 Web 历史。个人微信的正常聊天功能不受影响。

升级前已经选择个人微信的任务仍会照常执行并保存 Web 历史，但通知会直接记为失败，不会尝试发送。可在会话中修改该任务，将通知渠道改为其他渠道或仅保存 Web 历史。

第一版仅向本人发送，不支持指定其他用户、群组或任意收件人。Telegram 必须绑定个人私聊，Slack 使用本人私信。若同一渠道存在多个不同的绑定目标，系统会拒绝发送，请先在个人设置中解绑多余目标，再重新绑定本人账号。通知失败或送达状态未知时，通过 Web 查看结果；系统不会自动重发可能已经送达的通知。执行记录列表会直接显示通知失败及其原因，展开记录可查看完整结果：

| 提示 | 原因与处置 |
|---|---|
| 个人微信不支持定时任务主动通知 | 任务使用了个人微信。修改任务，改用其他渠道或仅保存 Web 历史 |
| 通知渠道未配置或未启用 | 管理员尚未配置或已停用该 IM 渠道。联系管理员检查 IM 集成 |
| 尚未绑定该通知渠道 | 当前账户未绑定该渠道。先完成绑定，或修改任务改用其他渠道 |
| 通知失败或送达状态未知 | 平台调用失败、超时或服务在发送中重启，无法确认是否送达。查看 Web 历史；管理员可按执行 ID 查询服务日志 |

Web 登录在线时，右下角向本人显示执行成功、失败或中断的汇总通知，样式与系统告警一致。右下角同时只显示一张卡片，新的普通事件通知或定时任务通知会替换原卡片，关闭后不会重新显示被替换的旧卡片。

定时任务卡片显示最新任务、执行状态、时间，以及当前批次的新结果数和失败数；执行超时会明确显示超时原因。点击**查看结果**或**查看失败详情**打开对应结果会话；没有历史结果时，可点击**查看执行记录**。卡片始终提供**查看全部执行记录**，用于查看本人各任务的近期结果。新结果数包含失败结果，失败数是其中失败或中断的数量；这些数字仅汇总当前提醒批次，关闭卡片或通过卡片打开结果、记录或授权页面后清零，不代表持久保存的未读数量。

历史列表和打开的任务、执行记录列表会同步刷新。接收通知不会切换当前会话或清空输入内容。主动取消只刷新状态，不弹出结果通知。

Web 通知仅在浏览器保持连接时送达，不是操作系统通知。关闭页面、离线或连接中断期间的通知不保证补发；重新登录、连接恢复或打开后台授权时，系统会检查授权及尚未同步的执行摘要，也可通过历史列表或执行记录查看结果。系统不会定时轮询授权状态。Web 通知与 IM 通知相互独立，无需选择 IM 渠道也可接收 Web 通知。

管理员可在 Agent 配置页设置 `SCHEDULED_TASK_TIMEOUT_SECONDS`（单位：秒，默认 180，范围 1–86400），修改对下一次执行生效。执行超时会记录为失败，保存到 Web 历史，并通过已选择的 IM 渠道通知本人；主动取消不发送结果通知。

## 8.13.3 查看执行记录与结果

任务列表显示标题、状态、下次执行、时区和通知渠道，每页默认 10 条，可使用底部分页控件翻页或调整每页条数。任务列表和执行记录均在固定表格区域内滚动，顶部页签和底部分页保持可见，不随记录条数移动；行尾更多菜单提供删除操作。列表中的时间及详情中的执行时间按任务时区显示。

左侧历史列表按日期分组，关联定时任务的来源会话在标题旁显示小闹钟。顶部的**会话**筛选框可切换**全部会话**和**有定时任务的会话**；切换筛选时回到第 1 页。底部提供上一页、当前页码和下一页，每页最多 30 条；没有上一页或下一页时，对应按钮不可点击。点击筛选框旁的小型**刷新**图标保留当前筛选并回到第 1 页。列表仅加载摘要，点击会话后才加载完整内容。查看本人历史、闹钟标识和筛选沿用 AI 问答查看权限，无需额外的定时任务管理权限。

每次执行结果追加到创建任务的原会话中，不另建结果会话。同一会话可以关联多个定时任务，也可以继续普通提问；定时结果消息保留原始内容，不能编辑或重新生成。小闹钟标识的是任务来源会话；停止并删除全部关联任务后，刷新列表即不再显示标识。

1. 打开 **AI 问答 → 定时任务 → 全部执行记录**，查看本人所有任务当前保留的执行记录。通过**任务名称**下拉框选择**全部任务**或某个任务；切换任务筛选时回到第 1 页。也可在**定时任务**页签点击任务标题，再切换到详情的**执行记录**，只查看该任务。
2. 系统按执行时间倒序展示表格，每页默认 10 条。全部执行记录同时显示任务名称和时区，时间按各任务时区显示。通过表格下方的分页控件翻页或调整每页条数；调整每页条数回到第 1 页，点击对话框上方的**刷新**图标保留当前页。
3. 点击行首展开按钮查看完整结果或错误信息。
4. 结果已同步时，点击**查看结果会话**，系统打开原会话并滚动到当次执行的结果消息；通知中的结果链接也定位到该消息。也可在左侧历史列表中打开对应会话。
5. 在原会话输入框中继续提问，或继续创建其他定时任务。发送普通提问后调用 AI，已保存的定时结果消息不会被修改。

执行开始前系统先记录执行信息。成功、失败、取消和执行中断均有记录；若历史会话暂未同步，可先在**执行记录**查看状态，稍后刷新。外部依赖故障可能导致结果会话暂时无法打开，不表示任务从未执行。

如需清理一条已结束的执行记录，在该行的更多菜单中选择**删除**并确认。此操作仅隐藏执行记录列表中的记录，**保留原会话中的结果消息**，任务后续仍按计划执行。排队、执行中或尚未结束的记录不能删除；已结束记录删除后，尚未完成的结果同步和后台清理仍会继续。删除最后一页的最后一条记录后，列表自动回到有效页。已删除记录不再产生新的通知；已经开始发送的通知仍可能送达。

### 8.13.3.1 执行记录保留策略

执行记录是仅供本人查看的近期记录，不是永久历史或未读通知中心。该保留策略仅清理执行记录，不会使任务自动过期、暂停或删除，周期任务继续按计划执行。每个任务通常最多保留最近 100 条完整记录，已结束记录最长保留至结束后 30 天；容量不足时，可更早回收已安全结束的旧记录。回收在存储提交或后台清理时进行，不保证到期时刻立即移除。

尚未结束的执行，以及仍需同步结果、完成通知或后台清理的记录会受到保护，因此不能将 100 条理解为包含所有待处理记录的绝对上限。没有可安全回收的空间时，系统会以容量错误暂停任务，不会静默丢弃失败记录。删除记录后，待同步结果和后台清理仍需完成，记录内容随后回收；原会话中已保存的结果消息不因执行记录到期或回收而删除。

累计执行次数与当前保留条数不同：失败执行也计入累计次数，删除、到期回收和修改任务均不重置累计次数。周期任务不再有生命周期累计 100 次的限制；单次任务执行后仍会完成。升级前因旧的 100 次限制而完成的周期任务，需要显式恢复，不会自动重新启用。

## 8.13.4 修改、暂停和恢复

任务操作位于任务详情的**常规**页签。修改配置和暂停执行是不同操作：暂停中的任务修改后仍保持暂停，需要单独恢复。

### 8.13.4.1 修改任务

1. 在详情点击**复制修改请求**，随后点击**返回来源会话**，或关闭对话框并新建普通会话。
2. 粘贴复制的请求，补充修改内容后发送。例如“将计划改为确认后 2 分钟执行一次，保留 Asia/Shanghai 时区、执行内容及仅保存 Web 历史”。
3. 等待 `edit_scheduled_task` 确认卡片，核对任务及完整新配置，确认时区后点击**执行**。
4. 返回任务详情刷新，确认计划已更新。复制请求本身不会修改任务。

同一来源会话可创建多个独立任务；新增请求不会自动替换旧任务。修改请求包含精确任务标识，避免同名任务或同一会话中的多个任务被误改。发生版本冲突时，应刷新并重新发起修改。

### 8.13.4.2 暂停和恢复

1. 点击**暂停**，在确认对话框中核对任务后确认。系统停止安排后续执行，并尝试取消在途执行；已有结果保留，已经开始发送的通知仍可能送达。
2. 暂停后详情显示**已暂停**，不显示下次执行时间。
3. 点击**恢复**并确认，系统校验本人授权，从下一次未来时间执行，不补跑已有记录。升级前因旧的 100 次限制而完成的周期任务，也在详情中点击**恢复**；已完成的单次任务不提供此操作。

如提示正在结束在途执行，应等待并刷新后恢复。已错过时间的单次任务不能直接恢复，需要设置新的未来计划。

### 8.13.4.3 重新授权

API Key 过期、被删除或用户权限失效时，执行可能失败，任务状态变为**需要授权**。在个人设置中准备新的本人 API Key，进入**定时任务 → 后台授权**重新保存，再进入对应任务详情点击**恢复**。更新凭据影响当前账户所有任务，但不会自动恢复它们，也不会重跑已失败的 AI 调用。

执行发现授权失效时会保留失败记录，并向在线的本人发送通知。失败原因、当前 Key 名称、到期时间和**重新授权**入口合并在同一张失败卡片中，不额外叠加授权卡片；没有执行结果卡片时，系统可单独显示授权提醒。点击**重新授权**可打开后台授权页，页面常驻提示当前 Key、到期时间、授权状态及受影响任务数。即使失效 Key 导致暂时无法保存历史结果会话，也可先查看执行记录，恢复授权后继续同步历史，不重新执行 AI。网络故障或服务暂时不可用会显示检查暂时失败，不会据此要求更换 Key 或永久暂停未来调度。

授权失效在执行或登录、连接恢复、打开后台授权等现有检查入口发现；系统不定时轮询，也不保证在 Key 到期前提前发现。应选择仍有效的本人 Key 并保存，再逐条恢复受影响任务。

## 8.13.5 停止任务与删除历史

停止任务会保留会话中的已有结果；删除会话则同时关闭该会话关联的全部定时任务。应根据目的选择操作。

| 目的 | 操作 | 结果 |
|---|---|---|
| 暂时不再执行 | 详情中点击**暂停**并确认 | 保留任务和结果，可恢复 |
| 永久停止 | 任务列表行尾更多菜单选择**删除**，或在详情中点击**停止并删除任务**并确认 | 停止后续执行，尽力取消在途执行并移出任务列表；会话中的已有结果保留，删除后不提供任务恢复 |
| 清理一条已结束执行记录 | 执行记录行的更多菜单中选择**删除**并确认 | 仅移除执行记录，保留原会话中的结果消息，不影响任务后续执行 |
| 删除会话及其中的结果 | 在左侧历史列表的更多菜单中选择**删除**，核对关联任务名单并确认 | 关闭该会话下的全部定时任务，删除会话及其中的所有普通消息和定时结果 |

删除确认框会列出受影响的定时任务名称。同一会话关联多个任务时，确认后全部关闭，不再安排后续执行。删除失败时应刷新确认状态，再重试；关闭任务或删除历史的任一步失败，都会保留会话供重试。部分任务可能已停止，应以刷新后的状态为准。

系统先保存会话关闭状态，取消相关任务并等待正在进行的结果同步结束，再删除历史会话。延迟到达的结果或任务创建确认不会重新生成已删除的会话或恢复其任务。系统保留用于防重复执行和审计的精简回执，不保留已删除会话中的报告内容。

## 8.13.6 常见问题与限制

下表说明当前版本的运行边界及建议处理方式。

| 现象或限制 | 处理方式 |
|---|---|
| 没有定时任务入口或无法加载 | 检查权限、服务状态及 AI 服务连接配置 |
| 创建后没有按预期时间执行 | 核对是否点击执行确认、任务时区、状态及下次执行时间 |
| 执行失败或中断 | 查看执行记录中的错误信息；服务重启时在途执行可能被标记为中断，不会自动重新调用 AI |
| 历史会话待同步 | 在执行记录查看结果，稍后刷新；不要重复创建任务来重试同步 |
| 结果会话不可用或已被删除 | 先刷新历史列表；已删除的会话不会通过此入口重新生成 |
| 本人任务达到数量上限 | 每人最多保留 20 个未删除任务，停止并删除不再使用的任务 |
| 旧周期任务因执行 100 次而完成 | 核对计划与授权后明确恢复；当前不再限制生命周期累计次数 |
| 执行记录保留 | 通常为最近 100 条、结束后最长 30 天的窗口；容量回收可更早发生，Web 历史不受影响 |
| 服务部署 | 当前只支持单实例调度及持久化数据目录，不支持多实例并行调度同一批任务 |

AI 结论受模型和可查询数据影响。设备标识、时间范围及缺失数据应明确写入执行要求，并在使用报告前核对。
